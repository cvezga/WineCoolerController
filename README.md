# WineCoolerController

A Java-based controller for a small thermoelectric wine cooler. The application is intended to run on a **Raspberry Pi 3 Model B+**, read the cooler temperature from a **DS18B20 sensor**, and control the cooling hardware through GPIO-connected relay modules.

The target cooler holds approximately eight bottles. The cooling design uses a Peltier module (the **TEC1-12710** has been considered for this project) with fans to remove heat from the hot side and circulate air.

> **Implementation note:** This README documents the project setup and intended hardware. Pin assignments, temperature thresholds, relay polarity, exact Java/GPIO library versions, and service paths must be filled in from the application's actual configuration and wiring before deployment.

## Features and goals

- Read temperature from a DS18B20 sensor.
- Run the control application in Java on a Raspberry Pi 3B+.
- Switch the Peltier cooling circuit through an appropriately rated relay or switching device.
- Control the cooler fan(s), according to the control logic implemented by the application.
- Use temperature hysteresis to avoid rapid ON/OFF switching around the target temperature.

## Hardware

| Component | Purpose |
|---|---|
| Raspberry Pi 3 Model B+ | Runs the Java application and controls GPIO outputs |
| DS18B20 temperature sensor | Measures the temperature inside the cooler |
| Peltier module, e.g. TEC1-12710 | Provides thermoelectric cooling |
| Heat sink and fan(s) | Remove heat from the Peltier hot side and move air |
| Relay module(s) or suitable DC switching device(s) | Switch the Peltier/fan power circuits from GPIO control signals |
| DC power supply | Supplies the Peltier module and fans |

A 12 V, 12.5 A (150 W) supply has been considered for the Peltier setup. Confirm the actual current and voltage requirements of every load before selecting the power supply and switching hardware.

### Electrical safety

- **Never power a Peltier module or fan directly from a Raspberry Pi GPIO pin.** GPIO pins provide control signals only.
- Use a separate, correctly rated power circuit for the Peltier module and fans.
- Verify relay/module ratings for the actual **DC** load. Do not assume an AC rating is suitable for switching the same current at DC.
- Use suitable fusing, wire gauge, connectors, and power-supply capacity.
- The Peltier hot side needs a properly mounted heat sink and reliable airflow. Do not run the Peltier module without adequate hot-side cooling.
- Establish a safe output state for startup, shutdown, sensor failure, and application errors.
- Confirm whether each relay is active-high or active-low before connecting the load.

## Raspberry Pi configuration

### 1. Enable 1-Wire

Enable the 1-Wire interface in Raspberry Pi OS using the system configuration mechanism available in that OS version, then reboot if necessary.

Check that the kernel exposes the 1-Wire devices:

```bash
ls /sys/bus/w1/devices/
```

A DS18B20 normally appears as a directory whose name starts with `28-`. Read its data with:

```bash
cat /sys/bus/w1/devices/28-*/w1_slave
```

The application should validate the sensor response and handle missing devices, CRC errors, and failed reads. Do not assume that every directory under `/sys/bus/w1/devices/` is a valid temperature sensor.

### 2. Check GPIO access

Confirm the GPIO library's installation requirements and permissions for the Linux user that will run the application.

Document the pin numbering convention used by the application:

- **BCM numbering** — GPIO numbers assigned by the Broadcom SoC.
- **Physical numbering** — pin positions on the 40-pin Raspberry Pi header.

Do not mix the two conventions. Verify every configured pin against the actual wiring.

### 3. Build

If the project uses Maven, build it from the repository root:

```bash
mvn clean package
```

The packaged JAR is normally created under `target/`. Use the filename generated by the project.

### 4. Run

For an executable JAR:

```bash
java -jar target/<application-jar>.jar
```

Replace `<application-jar>` with the actual JAR name. Add any application profile, configuration path, or JVM arguments required by the project.

## Temperature control

A temperature dead band (hysteresis) helps prevent relay chatter when the measured temperature is close to the target. A typical control sequence is:

1. Read the DS18B20 temperature.
2. Validate the reading before using it.
3. Turn cooling on when the temperature reaches the configured upper threshold.
4. Keep cooling on until the temperature reaches the configured lower threshold.
5. On a missing or invalid sensor reading, use the application's defined safe output state and log/report the problem.

The actual thresholds and fan/Peltier sequence must come from the implementation. The application should also account for relay polarity: a GPIO LOW signal does not necessarily mean that a relay is OFF.

## Troubleshooting

### No DS18B20 device appears

- Check that 1-Wire is enabled.
- Check the sensor wiring and required pull-up resistor.
- Reboot if the interface was just enabled.
- Run `ls /sys/bus/w1/devices/` again and look for a `28-...` device.

### Temperature readings fail

- Inspect the sensor's `w1_slave` file.
- Check the sensor status/CRC result and retry transient read errors.
- Verify the sensor connections and power.

### GPIO or relay does not behave as expected

- Confirm the GPIO numbering convention and physical wiring.
- Confirm the relay's active level (active-high or active-low).
- Verify the GPIO library setup and Linux permissions.
- Test the control output without the Peltier power load connected.

### Peltier or heat sink becomes too hot

- Switch off the cooling load if heat removal is inadequate.
- Check heat-sink contact, fan operation, airflow, and power-supply ratings.
- Do not operate the Peltier module without adequate hot-side cooling.
